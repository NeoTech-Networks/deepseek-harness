# @deepseek-ai/dsh-account-usage

[English](README.md) | 中文

## 摘要

本包报告订阅账号自身的限流窗口已经消耗了多少，并把它显示在输入框下方。以订阅授权（而非 API key）鉴权的服务商会计量两个窗口：一天内多次重置的滚动短窗口，以及每周窗口。这两个数字在会话里任何地方都看不到，因此用尽额度的第一个信号通常是回合进行到一半被拒绝。Host 侧读取已保存的授权凭证并向账号索取它自己的数字；浏览器侧在输入框下方的信息条上、会话统计行旁边放置一行简短读数 `5小时 3% · 每周 16%`，点击后展开的面板给出重置时间、按范围划分的每周窗口以及本月的额外用量支出。没有订阅授权的部署完全不显示任何内容。

<a id="use-this-package"></a>
## 使用本包

在同时挂载了凭证提供者与 `ui-conversation` 的组合中挂载本插件。Host 侧拥有 `accountUsage` Remote 命名空间及其唯一方法 `read`，该方法从短时缓存作答，因此多个打开的窗口只产生一次上游请求。浏览器侧启动一个页面级的读取器，并在 `conversation.composer.dock` 上注册一个条目。

### 读数的含义

两个数字是各自窗口的整数百分比。从 80% 起使用警告色，从 95% 起使用严重色。读数末尾的标记表示这些数字不是最新的实时读取，面板会说明属于三种原因中的哪一种：已保存的授权凭证已过期、正等待适配器的下一次模型调用刷新它；账号拒绝了该凭证；或者读取本身失败、屏幕上仍是上一次的数字。

### 读取节奏

空闲时每分钟读取一次，本页有会话正在运行时每二十秒一次，回合结束后不久再读一次，页面重新变为可见时也读一次。这一节奏跟随数字本身：账号的数字只在请求被计费时变化，因此在什么都没运行时加快轮询只会消耗请求而学不到任何新信息。

### 没有订阅的部署

当没有挂载凭证提供者、配置地址上没有存储记录、或存储的记录不是本服务能读取的授权凭证（例如是一个 API key）时，`read` 回答 `unsupported`。此时该条目不渲染任何内容，因此登录到其他服务商的安装不受影响。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现内部细节 - 点击展开</summary>

Host 侧由三条性质定义。凭证绝不离开 Host：凭证记录在 `load` 中读取并在同一次调用中使用，`AccountUsageSnapshot` 没有任何可以携带令牌的成员。这里绝不刷新凭证，因为拥有它的适配器会在自己的请求中刷新它，而第二个刷新者与之竞争可能作废某个仍在进行中的请求正在使用的令牌；过期的凭证报告 `stale` 并等待。任何失败都不会抛出：传输故障、拒绝以及无法读取的负载都变成快照上的一个状态，并携带最后一次真正读到的数字。

用量报告是服务商拥有的未公开端点，因此 `usage-endpoint.ts` 是唯一与它对话的模块，其 schema 刻意宽松：每个窗口都可为空，未知键被忽略，解析读不懂的结构降级为一次失败读取。一个缓存条目和一个进行中的 promise 由所有调用者共享；调用方的取消信号刻意不转发进这次共享读取。

浏览器侧每页只保留一个读取器，而不是每个会话一个，因为这个数字是账号级事实，打开第二个对话不应让轮询翻倍。dock 条目闭包持有该读取器，因为输入框 dock 单元没有声明 slot 注入面。

</details>

<a id="model-experience"></a>
## 模型体验

无，因为本包只是用账号自己的额度百分比回答一个浏览器读数，不注册任何面向模型的内容。

#### KV 缓存影响

无；这些数字通过 Remote 传输，不组装任何模型请求。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>


这些限制定义了当前的用量界面。它们是当前的包约束，不是通用的限流方案对比，也不是任务待办列表。

- **只支持一种服务商的报告结构** - 解析针对的是以两个具名窗口加一个扁平限额列表为键的订阅用量报告。以其他方式计量订阅的服务商需要自己的读取器，而不是一个配置项。
- **自身不做刷新** - 过期的凭证会一直报告 `stale`，直到拥有它的适配器在下一次模型调用时刷新它，因此长时间空闲会让数字明显过期而不是保持最新。
- **只有整数百分比** - 报告自身的利用率在显示时被舍入为整数百分比，因此不足半个百分点的窗口读作 0 而不是一个很小的非零数字。
