# Agent Note：原生逐 Bot 工具策略

状态：已实现

[English](2026-10-31-native-bot-tool-policy.md) | 中文

## 问题

DS Bot 会继承操作者的全部文件访问权限。文件沙箱策略是 Session 级的单一设置，而 Bot 的职责只写在指令里。阻止 SIG 内容 Bot 写入其他业务仓库的唯一手段是一个 PreToolUse hook，它在 harness 之外运行，并且只对 hook 桥接翻译的 Session 生效。该 hook 首次实测时还只按记录键读取 Bot 存储，因此对所有活跃调用都放行了。

## 决策

`@deepseek-ai/dsh-experimental-bot-tool-policy` 在 `tools/pre-execute` 检查调用，并以 `prepend: true` 注册，因为 Claude Code 和 Codex 的 hook 桥接使用同一阶段。无论挂载了哪些 hook 它都生效，被拒绝的调用不会到达任何 hook。

规则与该 hook 相同：除非授权覆盖目标路径，否则拒绝写入；任何 Bot 都不能写入操作者根目录；密钥文件在读取时以及出现在 shell 命令中时都被拒绝；非 Bot Session 永远不受检查。

策略保存在独立文件中，不迁移到 Bot 记录，因为迁移会改写操作者的线上存储。独立文件可以回退、比较和测试，而无需触碰状态。插件读取存储，且不写入这两个文件。授权沿用 DS Bot `browserGrants` 条目的字段，并在调用发生时解析。

Bot 的 Session 按记录键、`sessionId`、早期分段和群聊成员 Session 建立索引。撰写本文时所依据的存储中，31 个 Bot 里有 22 个没有 `sessionId`，因为其键仍是活跃 Session；群聊中还有 27 个成员 Session 从未被该 hook 索引。子代理按其父 Session 链顶端的 Bot 检查，因此派生子代理不会解除限制。

策略文件缺失、为空或格式错误时，调用会被放行并记录一条警告。损坏的防护不能让团队停摆，而读不到策略的防护也没有规则可用。

## 考虑过的替代方案

**保留 hook。** 它只对已翻译的 Session 生效，并且每次调用都依赖一个子进程。

**为 Bot 记录增加字段。** 出于上述原因被否决：存储由操作者决定如何修改，而策略文件可以单独回退。

**注册在 `tools/execute`。** 该阶段在所有 hook 之后运行，hook 会看到策略拒绝的调用。

**解析 shell 写入。** 误解析命令会阻塞正常工作，误拒绝的代价高于这个缺口。该缺口记录在包 README 中。

**失败时拒绝。** 一个有问题的策略文件会让所有 Bot 同时停摆。

## 影响

Bot 仍可通过 shell 写入。策略文件损坏时保护即告失效，只留下一条日志警告。本包以默认关闭的可选组合包形式分发，因为默认产品隔离规则禁止任何随附模板包含实验性包。部署方必须自行选中该组合包并提供策略文件；在部署完成且同一验收套件在该部署上通过之前，hook 保持不变。
