# Agent Note: 纯文本模型的自动图像描述

Status: implemented

[English](2026-09-08-vision-routing.md) | 中文

## 问题

纯文本模型（`deepseek-v4-pro` 或 `deepseek-v4-flash`）无法接受图像输入。提示接纳会以「Model does not support image input」拒绝带图像的消息，于是用户必须先把会话切到视觉模型才能读取附带的截图，之后再切回。

## 决策

新宿主插件 `@deepseek-ai/dsh-vision-routing` 注册 `ctx.visionRouting`，提供 `enabled()` 与 `describe(refs, signal?)`。提示接纳现在对纯文本选择先持久接纳图像，然后把视觉模型的描述作为同一用户消息中的额外文本块追加，而不是拒绝。描述作为用户消息的一部分落盘，因此对模型可见且可重建；图像块保留在消息中，读取回显与导出继续可用。

该行为由现有 `subagent-model-selection` 用户设置（「允许 Agent 为 Subagent 选择模型」开关）门控。仅当该偏好启用且至少命名一个候选路由时才活跃。视觉路由是第一个其模型声明 `image` 输入的被允许路由，回退到配置的 `visionRoute`（`deepseek-official` / `deepseek-v4-flash-vision-exp`）。失败的描述调用会追加简短的「描述不可用」说明而不是拒绝发送，门控关闭的纯文本选择保持现有拒绝。

## 考虑过的替代方案

**单独的设置卡片。** 单独的开关会重复操作者已经设置的子代理模型授权，并且会为一个本质是「视觉模型是被允许的子代理」的行为增加设置界面。

**为每张图启动一个子代理。** 完整的子代理循环比一次视觉模型调用更重，还有递归风险；描述是一次描述图片的调用，不是委托的编码任务。

**为描述新增会话事件。** 描述已经作为用户消息文本块持久化，因此专用事件类型和投影会在没有新能力的情况下增加会话格式界面。

## 影响

纯文本会话上每张附加图片都会在发送时产生一次视觉模型调用，并让该会话的提示接纳变慢一次调用。图像块保留在消息中，因此纯文本派发仍会在描述文本块旁边输出 `[image omitted...]` 占位；两者都会到达模型。
